# Margin architecture

Margin is a local-first Windows and macOS desktop application. Ordinary UTF-8 files are the source of truth. No import, database conversion, remote service, account, or extension runtime is required.

## Technology choices

Electron provides consistent Chromium rendering, native dialogs, isolated IPC, system trash and native PTYs on both target platforms. Tauri was evaluated: its smaller runtime is attractive, but would require a separate Rust PTY integration and platform webview validation. Electron's established node-pty integration reduces that complexity. Renderer Node integration is disabled, context isolation and Chromium sandboxing are enabled. No document gets an executable Node context.

React + TypeScript + Vite implement the application shell. Tiptap 3 uses ProseMirror transactions, history and a real contenteditable document; its official Markdown extension provides GFM import/export. Milkdown and Toast UI were considered. Tiptap offers direct, well-defined commands for tables and formatting, and a maintainable extension model. Its Markdown extension is beta, so regression coverage and conservative source-mode protection matter. Unsupported constructs are opened in source mode to avoid destructive conversion. Frontmatter is retained verbatim. Unedited files are never serialized simply because they were opened.

CodeMirror 6 provides language parsing, syntax highlighting, folding, completion, search/replace and indentation. It is lighter and simpler to bundle than Monaco for a workspace that does not require VS Code extensions or a complete language-service environment. xterm.js is the terminal emulator, node-pty supplies ConPTY on Windows and forkpty on macOS/Linux. A terminal is created only following an explicit UI action.

The PTY dependency is pinned to `1.2.0-beta.18`. Testing exposed an exited-console `AttachConsole` race in stable 1.1.0; the pinned upstream release handles that failure. Windows closure explicitly terminates the shell's process tree, then releases ConPTY and its drain worker. Regression tests check actual process termination and that the test runner exits without leaked PTY workers. This pre-release dependency and Tiptap's beta Markdown extension are documented release risks, not hidden behind a claim of universal production readiness.

Primary sources: [Electron security](https://www.electronjs.org/docs/latest/tutorial/security), [Tiptap Markdown](https://tiptap.dev/docs/editor/markdown/getting-started/basic-usage), [CodeMirror language packages](https://codemirror.net/examples/lang-package/), [node-pty](https://github.com/microsoft/node-pty), [Tauri sidecars](https://v2.tauri.app/learn/sidecar-nodejs/).

## Boundaries

- `electron/workspace.mjs`: root confinement, UTF-8 reads, optimistic revision checks, atomic writes, file tree, attachments and operations.
- `electron/references.mjs`: remark GFM AST reference discovery; destination-only edits retain surrounding Markdown bytes. Link resolution accounts for anchors, URL encoding, folder moves and the source document's new directory.
- `electron/transactions.mjs`: durable operation journals and rollback/recovery. Originals are retained in application data before multi-file changes. Incomplete transactions block writes until recovered.
- `electron/main.mjs` and `preload.cjs`: allowlisted, sender-validated IPC, window lifecycle, settings/session drafts, watching, workspace-scoped asset protocol.
- `electron/terminals.mjs`: PTY creation, dimensions, output and termination.
- `src/editors`: rich Markdown and code editor integration; content is kept in tab buffers until explicit save or configured autosave.
- `src/components/ContextMenu.tsx` and `src/lib/edit-menu.ts`: shared, viewport-constrained menus for editors, native text fields, tabs and explorer entries. Focus/selection are restored before actions; editor history and structural commands stay with Tiptap/CodeMirror. Native clipboard and input-edit commands use a fixed sender-validated IPC allowlist. Tab batch closing awaits the existing save/discard/cancel flow and stops on cancellation or save failure.
- P2 menus add a second portal for submenus with Left/Right keyboard navigation. Visual image edits operate on image nodes and never delete files; standalone Markdown images retain a paragraph wrapper for the inline-image schema. Local image/path/reveal IPC resolves through workspace confinement; `src/lib/image-clipboard.ts` decodes raster bytes in Chromium (including WebP/GIF/AVIF), draws at original resolution and sends validated PNG pixels to the native clipboard. Loads have a 30 MB input limit and HTTPS timeout. Remote previews reuse `ImagePreview` in a temporary dialog.
- `src/lib/terminal-links.ts`: hit testing through xterm's public buffer/cell API, accounting for soft wraps, wide characters and surrogate pairs. Terminal menu paste uses xterm's paste method to preserve bracketed-paste behavior; clearing only changes the view and does not terminate the PTY.
- `src/lib/sections.ts`: shared remark/GFM heading extraction, full readable titles, collision-safe Unicode anchors and encoded Markdown section links. Section copying writes Markdown text and a safely escaped HTML anchor to the clipboard, so Source gets Markdown and Visual gets a clickable link. The outline retains its 2 MB/500-item bounds; heading menus and link navigation cover the workspace file limit. At most eight documents up to 2 MB are cached. Visual menus derive headings from Tiptap nodes using the same anchor assignment. CodeMirror keeps normalized internal line positions while serializing the source's line-ending preference; raw formatter/outline offsets are translated and external updates do not create edits.
- `src/lib/formatting.ts`, `formatter.worker.ts`, `formatter-client.ts`: bundled Prettier standalone and explicit parser plugins, run in a worker without privileged APIs or executable workspace configuration. Default-on formatting applies once on opening a clean supported source buffer. Requests carry a document snapshot; an intervening edit cancels the result. Formatting is one isolated undo step, uses the configured indentation/line endings and follows autosave. Parser failures leave original code intact. The PHP plugin is limited to pure PHP and a conservative syntax target; mixed PHP/HTML is not reformatted automatically.
- `src/components/ImagePreview.tsx`: per-tab image transforms, a non-passive wheel listener for pointer-anchored zoom, pointer-capture panning and fit-on-resize. Zoom state is local to the mounted viewer and never enters filesystem writes.
- `src/lib/outline.ts` and `src/components/DocumentOutline.tsx`: debounced document structure from bundled CodeMirror language parsers, with stale-result cancellation, nested symbol ranges and exact source offsets. PHP syntax is masked by parsed text ranges for a second HTML pass, preserving tags around PHP blocks. Markdown frontmatter is masked without changing offsets. No document code is executed.
- `src/App.tsx`: tabs, conflict handling, layout, command palette and workspace operations.

## Integrity policy

Every save compares a SHA-256 revision with disk and refuses to overwrite external changes. Mutations are serialized. Moves preflight every Markdown reference, check original revisions again, journal originals, rename without intentional overwrite and atomically rewrite affected documents. Rollback restores the original state on ordinary failure. Crash recovery checks observed state before restoring so that later external edits are never overwritten. Symbolic links are not traversed. Unsaved buffers must be saved before reorganization; conflicts must be explicitly resolved. Deleted entries go through the OS trash. Local draft recovery is independent of autosave.

The reference index is rebuilt from workspace Markdown at operation time to include external changes; this favors integrity over speed for typical personal workspaces. Ignored directories are excluded deliberately and surfaced in settings. Large repositories can incur a noticeable preflight delay. Full LSP servers, split editor groups, collaborative editing and an extension ecosystem are outside this version.

## P1 search and navigation

Workspace content search runs in `electron/search.mjs` through `workspace:search` and `workspace:cancel-search`. Each request has an ID and AbortController; replacement requests and workspace changes cancel old work. The renderer debounces typing and rejects late responses. Search uses the confined workspace tree/read APIs, respects ignored paths and skips unreadable/binary files. Dirty renderer buffers overlay disk contents, including empty buffers. Literal matching is shared with visual search in `electron/search-core.mjs`; filters support comma-separated filename/path globs, case and Unicode whole words. Results carry raw UTF-16 ranges, line/column and snippets. The UI exposes the 500-result limit. Results open Source and suppress automatic formatting for that tab, including after session restoration, so navigation does not edit or shift the target.

Visual document search uses a Tiptap plugin with mapped decorations and text-block matches spanning inline marks. Replacements run in a single ProseMirror history transaction. The 2000-match cap is displayed, and Replace all is disabled at that cap. Read-only selection/search transactions skip StarterKit’s trailing-paragraph insertion to avoid creating edits while navigating.

Visual spelling uses a separate decoration plugin instead of Chromium's incremental native markers. `Intl.Segmenter` tokenizes whole text blocks across formatting boundaries, preserving UTF-16 positions and excluding inline code and code blocks. After a short debounce, unique words are checked in batches against `nspell` and bundled Dutch, US/UK English, French and German Hunspell dictionaries. Checks run locally through the isolated preload/validated IPC path; native spellcheck is disabled to avoid competing verdicts. Dictionary parsing and word checks run in a Node worker so switching languages cannot block the application process. The worker and its dependencies are unpacked alongside ASAR in packaged builds. Disabling or switching dictionaries terminates the old worker. A per-language bounded word cache gives identical occurrences the same result. Settings and dictionary readiness carry a revision, while editor runs have a generation and document snapshot: late batches cannot publish results after edits, language changes, disabling, hiding or destroying an editor. View-only transactions do not alter notes, selections, trailing paragraphs or undo history. Dictionary load failures are shown in Preferences. Dictionary data retains the upstream licenses distributed in each `dictionary-*` dependency (OpenTaal for Dutch, SCOWL for English, Grammalecte for French and igerman98 for German); `nspell` is MIT licensed.

`editor-position.ts` registers capture/restore/reveal handles for both editors. Snapshots store native selection/scroll plus portable Markdown source offsets, a visible-text anchor and a text signature. Parsed Markdown and ProseMirror text projections transfer selections across formatting, metadata, code and CRLF. Same-mode unchanged text restores native positions; mode changes map the source positions and reading anchor. Scroll/selection persistence is debounced separately from document state so it does not defer autosave.

`NavigationHistory` stores up to 100 file/section locations in memory, checkpoints the departing view and truncates forward history when a new route is chosen. Outline jumps into an already active editor reveal synchronously to avoid racing immediate typing. Rename/move remaps history and saved positions; Trash removes affected entries. Per-workspace saved sessions include validated editor snapshots and at most 20 closed-tab metadata entries. Closing is recorded only after save/discard succeeds; closed metadata contains no discarded buffer contents. Navigation history itself is not persisted.

## P2 quality of life

`quick-open.ts` ranks fuzzy subsequences with filename, word-boundary, contiguous-match and suffix bonuses. Empty queries use up to 100 recent file paths saved per workspace; paths follow app moves and Trash. Optional `:line[:column]` suffixes map raw UTF-16 source offsets, including CRLF, and use the shared navigation registry. Direct line navigation suppresses autoformatting. Opening a file no longer restores over pointer/keyboard input made during activation.

`file:save-copy` writes a renderer snapshot under a new confined workspace-relative name with exclusive creation and fsync, serialized by Workspace.mutate. It refuses collisions and invalid/oversized text, and rebases Markdown references using the existing duplicate semantics. The original file is not renamed. Save as replaces the original tab only after success and only if the buffer still equals the saved snapshot; newer edits remain open. Save a copy retains the original tab. Pins and order persist in sessions, pins partition tabs ahead of regular tabs, drag/menu ordering stays inside that partition, and bulk close skips pins. Closed-tab metadata retains the pin state.

DocumentOutline subscribes to the shared position events and uses source offsets to mark the current item. Scroll events use the reading anchor when the caret is outside the viewport. Filtering keeps matching ancestors; collapse state is local to the current document. LinkPicker shares fuzzy filename ranking and the Markdown heading parser, reads dirty tabs before disk, encodes workspace-root file/section hrefs and cancels stale reads. The link dialog snapshots its original text selection; Cmd/Ctrl+K also synchronizes a pending native DOM selection with the editor before opening.

Explorer rows use a roving tab stop and visible-tree keyboard traversal, folder/parent arrows, typeahead and existing keyboard context menus. `terminal:create` optionally accepts a confined directory, verifies it is a directory and still belongs to the current workspace, then passes cwd directly to node-pty rather than issuing a shell cd command.

ConflictDiff aligns editor/disk text with a line LCS after trimming common ends. The matrix is capped at two million cells, falling back to paired changed blocks for larger divergent regions. Parsing/preview uses the first 5001 lines per side and displays at most 5000 aligned rows with an explicit limit notice. Fixed-height rows, line numbers, gap rows and vertically synchronized native scroll panes keep changes aligned. Horizontal scrolling remains independent so a shorter line in the other pane cannot limit reading a long line. Original buffers remain intact for save/recovery actions.

## P3 quality of life

Preference updates are serialized, including history pruning, so overlapping UI changes cannot overwrite one another. Reading preferences are validated numeric settings exposed as CSS variables under the application root, independently of code font size. Slash insertion uses a Tiptap plugin that detects a slash prefix in a paragraph/heading text selection, excludes code and inline paths, and routes keyboard input to a portal list. Block commands delete the query and invoke existing editor commands under one history boundary. Image insertion keeps the query through chooser cancellation, gates duplicate requests and rejects a stale document snapshot before editing.

`FileHistory` stores UTF-8 snapshots in application-data `history/`, with UUID blob names and an atomically written index. Workspace hashes and workspace-relative paths scope list/read/checkpoint IPC; snapshots are checked against their stored content hash before reading. Workspace.save captures the previous disk version before a changed write, rechecks its optimistic revision after capture and only then replaces the file. Identical consecutive contents are deduplicated. History retention caps snapshots per file, total content bytes across workspaces and 5000 total index entries; startup removes unindexed blob leftovers. History is optional and distinct from move journals/drafts. A restore checkpoints current editor contents first when enabled, then changes only the open buffer. History path metadata follows committed app moves, with a returned warning if metadata could not follow an otherwise successful move.

Explorer multi-selection maintains a separate focused row and range anchor, supports modifiers/ranges/typeahead and carries selected paths in drag data. `selectionRoots` limits requests to 100 paths and excludes selected descendants of selected parents. Batch preflight validates all sources, destination folders, duplicate names (conservatively ignoring case), existing destinations and self-descendant moves before any rename. `rewriteReferencesMany` parses each Markdown note once and remaps all selected targets together, including links between moved notes. Transactions.moveMany records one journal for paths and original affected bytes; rollback/restart recovery locates edits according to which sources actually moved, validates all hashes before restoring and pauses on later external changes. Group Trash preflights all paths but reports each native Trash result separately, so only confirmed removed items leave the UI.

Split sessions store two distinct open paths and the focused active tab. There remains one editor instance per path, avoiding competing copies of a dirty file. Two visible panes have independent modes, selections, scroll containers and shared per-file save/conflict handling; focus chooses the target for normal commands/navigation. A new path replaces the focused pane, while an already-visible path receives focus. Both visible editors restore view state without stealing focus and contribute snapshots to session persistence. App moves/Save As remap pane paths; closing a pane collapses the layout while keeping files open. Image viewers remain per-file instances with independent transforms; their zoom is not persisted across restart.
